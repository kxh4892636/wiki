# InnoDB 与 MyISAM 有什么区别，怎么选存储引擎？

## 常见问题

- MySQL中 InnoDB 和 MylSAM 的区别是什么？
- MySQL 有哪些常见的存储引擎？它们的区别是什么？

## 概念索引

- 存储引擎: 负责表数据读写与索引的实现层;
- InnoDB: 事务型引擎, 行锁、MVCC 与崩溃恢复;
- MyISAM: 无事务、表锁的旧默认引擎;
- MEMORY: 数据放在内存里的临时引擎;
- ARCHIVE: 只写少读的高压缩归档引擎;
- 选型: 按事务、并发与恢复需求挑引擎, 默认用 InnoDB;

## 存储引擎在 MySQL 里处于什么位置？

- 分层: Server 层负责解析、优化、执行, 引擎层负责真正的存取;
- 粒度: 建表时用 `ENGINE=` 指定, 也可 `ALTER TABLE ... ENGINE=` 转换;
- 差异: 事务、锁粒度、索引组织、崩溃恢复都随引擎变化;
- 边界: 优化器与 SQL 语法在 Server 层, 引擎只决定怎么读写;

## InnoDB 与 MyISAM 有哪些区别？

| 项 | InnoDB | MyISAM |
| --- | --- | --- |
| 事务 | 支持 | 不支持 |
| 锁粒度 | 行锁 | 表锁 |
| 并发读写 | 读不阻塞写, 靠 MVCC | 写会阻塞所有读 |
| 索引组织 | 聚簇索引, 叶子存整行 | 索引与数据分离, 叶子存地址 |
| 外键 | 支持 | 不支持 |
| 崩溃恢复 | redo log 自动恢复 | 可能要用 `REPAIR TABLE` |
| 整表计数 | 需扫描索引 | 维护行数, 直接返回 |
| 空间占用 | 较大 | 较小 |

- 文件: MyISAM 三个文件 `.frm`、`.MYD`、`.MYI`;
- 版本: MySQL 8.0 已移除 `.frm`, 改用数据字典;
- 地址: MyISAM 索引叶子存的是行在数据文件里的地址, 不是主键;

## 还有哪些常见引擎？

| 引擎 | 特点 | 场景 |
| --- | --- | --- |
| InnoDB | 事务、行锁、MVCC、外键 | 绝大多数业务表 |
| MyISAM | 表锁、无事务、占用小 | 只读或读多写少的旧表 |
| MEMORY | 哈希或 B 树索引, 数据在内存 | 临时表、会话缓存 |
| CSV | 逗号分隔文本, 无索引 | 导入导出 |
| ARCHIVE | 高压缩, 只支持插入与查询 | 日志归档 |
| BLACKHOLE | 丢弃写入, 只留 binlog | 复制中继测试 |

- 默认: MySQL 8.0 的默认引擎是 InnoDB;
- 判断: 需要事务与并发写入时, 不必再考虑其他引擎;
- 粒度: 引擎按表选择, 同一个库可以有不同引擎的表;

## 从 MyISAM 迁到 InnoDB 要注意什么？

- 语义: 整表计数从常数时间变成扫描, 大表要另做统计表;
- 锁: 表锁换成行锁, 但没索引的更新仍会锁住大量行;
- 事务: 依赖自动提交的代码要补显式事务与异常回滚;
- 空间: 聚簇索引会重排数据, 迁移前预留磁盘与维护窗口;
- 验证: 迁移后用同样负载对比延迟、锁等待与复制延迟;
- 手册: 各引擎的特性见 [MySQL 存储引擎](https://dev.mysql.com/doc/refman/8.0/en/storage-engines.html);
