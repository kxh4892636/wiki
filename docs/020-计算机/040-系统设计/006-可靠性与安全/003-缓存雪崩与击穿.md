# Redis 如何防止缓存雪崩和缓存击穿?

## 常见问题

- 简述 Redis 中如何防止缓存雪崩和缓存击穿

## 概念索引

- 穿透: 查不存在的数据, 请求全落到数据库;
- 击穿: 单个热点键过期, 大量请求同时回源;
- 雪崩: 大批键同时过期或缓存整体不可用;
- 互斥重建: 只让一个请求回源, 其余等待;
- 逻辑过期: 值不设 TTL, 过期标记由后台异步刷新;
- 布隆过滤器: 用位图判断一定不存在, 有假阳性无假阴性;

## 三种失效怎么区分?

| 现象 | 范围 | 触发 |
| --- | --- | --- |
| 穿透 | 单请求反复 | 查不存在的键 |
| 击穿 | 单个热点键 | 键过期的瞬间 |
| 雪崩 | 大批键 | 同时过期或实例故障 |

- 共同后果: 数据库瞬间承受本该被缓存挡住的流量;
- 处理思路: 穿透靠过滤, 击穿靠串行化, 雪崩靠打散与冗余;

## 雪崩怎么防?

- TTL 加随机: 在基础过期时间上加随机抖动, 避免整点一起失效;
- 多级缓存: 本地缓存加 Redis, 缓存整体挂掉时本地还能挡一阵;
- 高可用: 主从加哨兵或 cluster, 单分片故障只影响部分键;
- 预热: 活动前批量灌入缓存, 避免开服瞬间集体回源;
- 保护: 数据库前面加限流与熔断, 超阈值快速失败而不是被打穿;
- 降级: 返回旧值或静态兜底页, 保住核心链路;

## 击穿怎么防?

- 互斥锁: 未命中时 `SET lock:key 1 NX PX 3000`, 拿到锁的回源, 其余短暂等待后重读;
- 单飞: 进程内用 singleflight 合并同一键的回源, 减少 Redis 与数据库压力;
- 逻辑过期: 值里带过期时间, 读到已过期先返回旧值, 再异步刷新;
- 永不过期: 热点键不设 TTL, 变更时主动更新;
- 取舍: 互斥保证新鲜但有等待, 逻辑过期延迟低但可能返回旧值;

```text
v = GET key
if v != null: return v
if SET lock:key 1 NX PX 3000:
    v = query_db(); SET key v EX 300; DEL lock:key; return v
sleep 50ms
return GET key ?: 默认值
```

## 穿透怎么防?

- 空值缓存: 查不到也写一个短 TTL 的空标记, 挡住重复查询;
- 布隆过滤器: 前置判断键是否存在, 判定不存在就直接返回;
- 校验: 非法 id 在入口就拒掉, 不要进缓存层;
- 限流: 对同一来源的异常查询做频率限制;
- 注意: 空值缓存占内存, TTL 要短, 新增数据时要能及时生效;
