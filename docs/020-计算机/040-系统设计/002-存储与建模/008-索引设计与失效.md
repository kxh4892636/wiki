# 索引怎么设计，什么情况下会失效？

## 常见问题

- 数据库如何设计索引，如何优化查询？
- 数据库有哪些常见索引？数据库设计的范式是什么？
- MySQL 的索引什么情况下会失效？
- 什么时候索引会失效？
- 数据库反范式设计会出现什么问题？

## 概念索引

- 选择性: 不同取值数除以总行数, 越高越适合建索引;
- 联合索引: 按查询组合排序的多列索引;
- 覆盖索引: 让查询只读索引不回表;
- 隐式转换: 类型不一致时索引列被当成表达式;
- 函数索引: 对表达式建索引, 支持计算后再过滤;
- 反范式: 为读性能有意冗余, 代价是一致性维护;

## 设计索引的步骤是什么？

- 起点: 从慢查询里挑扫描行数多的语句, 不从字段清单出发;
- 组合: 等值条件在前, 范围与排序在后, 尽量覆盖返回列;
- 数量: 单表索引控制在 3 到 5 个, 写密集表更少;
- 长度: 长字符串用前缀索引, 主键用短自增列;
- 验证: 用接近生产的数据量跑 `EXPLAIN`, 对比 `rows` 与真实耗时;

## 常见索引类型有哪些？

| 类型 | 说明 | 典型场景 |
| --- | --- | --- |
| 主键索引 | 聚簇、唯一、非空 | 每表必备 |
| 唯一索引 | 保证该列不重复 | 业务唯一键 |
| 普通索引 | 只加速查询 | 过滤与排序列 |
| 联合索引 | 多列组合排序 | 多条件查询 |
| 前缀索引 | 只索引前 N 个字符 | 长 URL、邮箱 |
| 全文索引 | 分词倒排检索 | 文章搜索 |

- 选择: 先满足查询形状, 再考虑类型与数量;
- 匹配: 唯一约束用唯一索引, 范围检索用普通或联合索引;
- 前缀: 长字符串只索引前 N 个字符, 覆盖不到就加长;

## 范式要求什么，为什么还要反范式？

| 范式 | 要求 |
| --- | --- |
| 1NF | 列不可再分, 不存重复组 |
| 2NF | 非主属性完全依赖候选键 |
| 3NF | 消除非主属性对键的传递依赖 |
| BCNF | 每个非平凡依赖的决定项都是超键 |

- 收益: 减少冗余, 同一事实只存一处;
- 反范式: 冗余计数、冗余名称、宽表, 用空间换掉联接;
- 问题: 冗余数据要有人维护, 部分更新失败就长期不一致;
- 前提: 先说清谁写、何时写、写错了怎么修;

## 索引什么时候会失效？

| 写法或条件 | 原因 | 改法 |
| --- | --- | --- |
| `WHERE DATE(created_at) = '2026-01-01'` | 列上套函数 | 改成范围比较 |
| 字符列比较数字常量 | 隐式类型转换 | 传同类型值 |
| `LIKE '%abc'` | 前导通配符 | 改后缀匹配或用全文索引 |
| `a = 1 OR b = 2` 且 b 无索引 | OR 一侧无索引 | 拆成 `UNION` 或补索引 |
| (a, b, c) 上查 a 与 c | 跳过中间列 | 调整列顺序 |
| 只有两种取值的状态列 | 区分度太低 | 不建, 或做覆盖索引 |

- 统计: 优化器按采样估算, 分布极端时会选错索引;
- 排序: `ORDER BY` 与索引顺序不一致时出现 `Using filesort`;
- 例外: 表很小的时候全表扫描本来就更快, 不算失效;

## 索引失效也可能是优化器的选择吗？

- 判断: `type=ALL` 但表只有几百行, 全表扫描确实更便宜;
- 统计: `ANALYZE TABLE` 刷新统计信息, 让估算更准;
- 强制: `FORCE INDEX` 仅在确认计划选错时用, 数据变化后要复查;
- 观测: 结合慢日志与 `Handler_read_%` 计数, 不要只看单次计划;

## EXPLAIN 判读要点有哪些？

| 列 | 判读 |
| --- | --- |
| `type` | 从 `system` 到 `ALL` 由好到坏 |
| `key` | 为空说明没走索引, `possible_keys` 只是候选 |
| `rows` | 估算扫描行数, 与返回行数比值越小越好 |
| `Extra=Using index` | 覆盖索引, 不回表 |
| `Extra=Using where` | 回表后再过滤 |
| `Extra=Using temporary` | 用了临时表, 常见于分组与去重 |

- 重点: `type=ALL` 且 `rows` 很大, 是首要优化对象;
- 区分: `Using index` 不回表, `Using index condition` 仍要回表;
- 手册: `type` 与 `Extra` 的完整取值见 [EXPLAIN 输出格式](https://dev.mysql.com/doc/refman/8.0/en/explain-output.html);
