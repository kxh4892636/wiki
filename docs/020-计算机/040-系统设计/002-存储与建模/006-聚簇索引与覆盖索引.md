# 聚簇索引、二级索引与覆盖索引是什么关系？

## 常见问题

- 聚簇索引和非聚簇索引有什么区别？
- 简述 MySQL 常见索引类型，介绍一下覆盖索引
- 唯一索引与普通索引的区别是什么？使用索引会有哪些优缺点？
- 数据库主键索引和唯一索引有什么区别？

## 概念索引

- 聚簇索引: 叶子存整行的索引, InnoDB 里就是主键索引;
- 二级索引: 叶子存索引列与主键的辅助索引;
- 回表: 二级索引查完再按主键查一次聚簇索引;
- 覆盖索引: 要的列都在索引里, 不用回表;
- 唯一索引: 要求索引列取值不重复的索引;
- 主键索引: 唯一且非空, 并被选作聚簇索引的那一个;

## 聚簇索引和非聚簇索引差在哪？

| 项 | 聚簇索引 | 非聚簇索引 (如 MyISAM) |
| --- | --- | --- |
| 数据位置 | 叶子页就是数据行 | 索引与数据分开, 叶子存行地址 |
| 数量 | 每表一个 | 每表多个 |
| 主键点查 | 一次索引查找 | 两次: 先索引再按地址取行 |
| 插入 | 按主键顺序聚集 | 顺序追加, 靠地址定位 |
| 二级索引代价 | 必须回表 | 按地址直接取行 |

- InnoDB: 没有非聚簇选项, 二级索引也是 B+ 树, 只是叶子不带整行;
- 选主键: 没有主键时用第一个非空唯一索引, 再退化为隐藏行 ID;
- 代价: 主键很长会让每个二级索引都变大;

## 覆盖索引怎么生效？

```sql
CREATE INDEX idx_name_age ON users(name, age);
EXPLAIN SELECT name, age FROM users WHERE name = 'k';
-- type=ref, key=idx_name_age, Extra=Using index
```

- 条件: `SELECT`、`WHERE`、`ORDER BY` 用到的列都在同一个索引里;
- 收益: 省掉回表, 少一半以上随机 IO;
- 反例: `SELECT *` 基本覆盖不了, 除非索引包含全部列;
- 设计: 高频列表把要展示的列放到联合索引尾部;

## 唯一索引和普通索引差在哪？

| 项 | 唯一索引 | 普通索引 |
| --- | --- | --- |
| 约束 | 不允许重复值 | 允许重复 |
| NULL | 允许多行 NULL | 允许 |
| 写入 | 先查重, 目标页不在内存也得读盘 | 可先写 change buffer 再合并 |
| 查询 | 等值命中一行即停 | 可能继续扫相邻重复项 |
| 死锁 | 并发插入同一键更容易竞争 | 相对少 |

- 索引优点: 加速过滤与排序, 唯一索引还能兜住重复数据;
- 索引缺点: 占空间、写放大、每个索引都要维护;
- 数量: 单表索引通常控制在 3 到 5 个;

## 主键索引和唯一索引差在哪？

- 非空: 主键列不允许 NULL, 唯一索引可以有多行 NULL;
- 数量: 一张表只能有一个主键, 唯一索引可以有多个;
- 位置: 主键索引就是聚簇索引, 唯一索引是二级索引;
- 选择: 没有业务主键时用自增列, 不要用随机 UUID 当聚簇键;
- 关系: 主键索引是加了非空约束的唯一索引, 差别在数量与是否聚簇;

## EXPLAIN 怎么确认有没有回表？

- `Using index`: 覆盖索引, 只读索引页;
- `Using index condition`: 索引下推, 过滤后仍要回表取整行;
- `key_len`: 用了联合索引的几个列, 比预期小说明只用到前缀;
- `rows` 乘以 `filtered`: 估算实际参与比较的行数;
