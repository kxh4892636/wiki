# join、left join 与聚合函数怎么用？

## 常见问题

- MySQL 中 join 与 left join 的区别是什么？
- 简述 SQL 中左连接和右连接的区别
- 数据库查询中左外连接和内连接的区别是什么？
- MySQL 常用的聚合函数有哪些？
- MySQL 中 varchar 和 char 的区别是什么？
- 模糊查询是如何实现的？

## 概念索引

- 内连接: 只保留两表都能匹配上的行;
- 左外连接: 保留左表全部行, 右表缺失补 NULL;
- 右外连接: 保留右表全部行, 等价于左右调换的左连接;
- 聚合函数: 把一组行压成一个值;
- 三值逻辑: NULL 参与比较得到 UNKNOWN, 不是 FALSE;
- 模糊查询: 用 `LIKE` 或全文索引做部分匹配;

## 内连接与外连接差在哪？

| 写法 | 保留哪些行 | 典型用途 |
| --- | --- | --- |
| `A JOIN B ON ...` | 只有匹配上的行 | 统计已下单用户 |
| `A LEFT JOIN B ON ...` | 左表全部, 右表缺失补 NULL | 列表带可空关联 |
| `A RIGHT JOIN B ON ...` | 右表全部 | 等价于调换顺序的左连接 |
| `A CROSS JOIN B` | 笛卡尔积 | 生成组合 |

- 差别: 没匹配上的行留不留, 以及缺的一侧补 NULL;
- 内连接: `ON` 与 `WHERE` 换个位置, 结果不变;
- 外连接: 条件写 `ON` 还是 `WHERE`, 结果会变;

## left join 有哪些常见坑？

```sql
-- 陷阱: 右表条件写到 WHERE, 补 NULL 的行被过滤掉, 退化为内连接
SELECT u.id, o.amount
  FROM users u LEFT JOIN orders o ON o.user_id = u.id
 WHERE o.status = 1;

-- 改法: 条件放进 ON, 需要判断缺失时单独写 IS NULL
SELECT u.id, o.amount
  FROM users u LEFT JOIN orders o
    ON o.user_id = u.id AND o.status = 1;
```

- 膨胀: 一对多连接会让左表行重复, 聚合前先确认基数;
- 计数: `COUNT(o.id)` 只数非 NULL, `COUNT(*)` 会把补 NULL 的行算进去;
- 索引: 关联列都要有索引, 否则每条主表行都触发一次子表扫描;

## 聚合函数怎么用？

| 函数 | 作用 | 注意 |
| --- | --- | --- |
| `COUNT(*)` | 行数 | 包含 NULL 行 |
| `COUNT(col)` | 非 NULL 个数 | 跳过 NULL |
| `COUNT(DISTINCT col)` | 去重计数 | 需要排序或哈希 |
| `SUM`、`AVG` | 求和、平均 | 忽略 NULL, 全 NULL 返回 NULL |
| `MAX`、`MIN` | 极值 | 有索引时可快速取值 |

- 顺序: `WHERE` 在分组前执行, `HAVING` 在分组后过滤;
- 空组: 整张表没有行时, `COUNT` 返回 0, 其余聚合返回 NULL;
- 性能: 分组列有索引可省掉临时表与排序;

## varchar 和 char 差在哪？

| 项 | CHAR | VARCHAR |
| --- | --- | --- |
| 长度 | 固定, 0 到 255 字符 | 可变, 0 到 65535 字节 |
| 存储 | 右补空格到定长 | 1 到 2 字节长度前缀加内容 |
| 取值 | 默认去掉尾随空格 | 原样保留 |
| 适用 | 定长短码, 如国家码 | 名字、地址、URL |
| 行限制 | 同样受行大小限制 | 整行 65535 字节所有列共享 |

- 选择: 长度稳定用 CHAR, 差异大用 VARCHAR;
- 索引: VARCHAR 越长索引越大, 必要时用前缀索引;
- 长度: 声明的是字符数, utf8mb4 下一个字符最多占 4 字节;

## 模糊查询怎么做？

- 前缀匹配: `LIKE 'abc%'` 能走索引, 定位到前缀起点后顺序读;
- 包含匹配: `LIKE '%abc%'` 不走 B+ 树, 退化为全表扫描;
- 全文: `FULLTEXT` 索引加 `MATCH ... AGAINST` 适合文本检索;
- 外部: 数据量大时交给搜索引擎的倒排索引;
- 技巧: 确定性后缀可存反转列, 再用前缀匹配;
- 手册: `CHAR` 与 `VARCHAR` 的存储规则见 [字符串类型](https://dev.mysql.com/doc/refman/8.0/en/char.html);
