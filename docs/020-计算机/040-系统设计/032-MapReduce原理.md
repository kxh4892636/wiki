# MapReduce 的原理是什么？

## 常见问题

- 简述 MapReduce 的原理

## 概念索引

- 分片: 输入按块切成多个 split, 一块对应一个 map 任务;
- Map: 对每条记录产出键值对;
- Shuffle: 按 key 分区、排序、搬运到对应 reducer;
- Combine: 在 map 侧做局部聚合, 减少网络传输;
- Reduce: 对同一 key 的所有值做归并;
- 容错: 任务失败就重跑, 用冗余执行对抗慢节点;

## 一条数据流是怎么走的？

```mermaid
flowchart LR
  A[输入分片] --> B[Map]
  B --> C[Combine 可选]
  C --> D[Shuffle 分区与排序]
  D --> E[Reduce]
  E --> F[输出到 HDFS]
```

- 划分: 输入文件按块大小切 split, 通常等于一个 HDFS 块;
- 并行度: map 数由 split 数决定, reduce 数由配置指定;
- 搬运: Shuffle 是全流程唯一的跨节点大流量, 也是主要瓶颈;
- 输出: 每个 reduce 写一个结果文件, 文件数等于 reduce 数;

## Map 与 Reduce 各做什么？

| 阶段 | 输入 | 输出 | 谁决定 |
| --- | --- | --- | --- |
| Map | 一条记录 | 若干键值对 | 业务代码 |
| Combine | map 输出的一部分 | 同 key 的局部归并结果 | 业务代码, 可选 |
| Shuffle | map 输出 | 按 key 分组的有序流 | 框架 |
| Reduce | 一个 key 加值列表 | 若干键值对 | 业务代码 |

```text
词频统计:
map("a b a")      -> (a,1) (b,1) (a,1)
combine           -> (a,2) (b,1)
shuffle           -> a:[2, ...]  b:[1, ...]
reduce("a", [2,3]) -> (a,5)
```

- Combine 的前提: 聚合满足结合律与交换律, 求和可以, 求平均不行;
- 排序: reduce 拿到的值默认按 key 升序, 二次排序靠自定义分区与比较器;

## 故障与慢节点怎么处理？

- 任务失败: map 或 reduce 抛异常, 框架在别的节点重跑该任务;
- map 输出丢失: 节点宕机后已完成 map 要重跑, 因为中间结果在本机磁盘;
- 慢节点: 同一任务在另一节点冗余执行, 先完成的为准, 即推测执行;
- 幂等: 重跑要求 map 与 reduce 输出可覆盖写, 不能追加副作用;
- 数据本地性: 调度优先把 map 放到数据所在节点, 省一次网络传输;

## 与后来的计算引擎有什么区别？

- MapReduce: 每个作业落盘一次, 迭代算法要串联多个作业, IO 放大;
- Spark: 用内存中的 RDD 血缘代替落盘, 迭代快一个量级;
- 流处理: Flink 等按事件处理, 不依赖批的分片模型;
- 仍适用的场景: 超大规模一次性批处理, 对内存要求低, 容错简单;
