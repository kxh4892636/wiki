# Gulp 和 Grunt 各有什么优势与劣势？

## 常见问题

- 了解过 Gulp 和 Grunt 吗？简述他们的优势以及劣势

## 概念索引

- 任务运行器: 把构建拆成可独立执行的任务;
- 配置驱动: 用对象描述每个任务做什么;
- 代码驱动: 用函数调用串起任务;
- 流: 数据在内存管道里逐段处理;
- 插件粒度: 一个插件只做一件事;
- 增量构建: 在流式任务上按文件时间戳跳过;

## Grunt 怎么工作？

- 入口: `Gruntfile.js` 里调用 `grunt.initConfig` 声明配置;
- 任务: `grunt.registerTask` 把多个子任务排成队列;
- 插件: `grunt-contrib-uglify` 等按配置读写文件;
- 优势: 配置直观, 插件齐全, 学习成本低;
- 劣势: 每个任务都落盘, 文件多时 IO 成为瓶颈;
- 劣势: 配置对象层级深, 复杂流程难以表达条件与复用;

```js
module.exports = (grunt) => {
  grunt.initConfig({
    uglify: { build: { files: { 'dist/app.js': ['src/app.js'] } } },
  });
  grunt.loadNpmTasks('grunt-contrib-uglify');
  grunt.registerTask('default', ['uglify']);
};
```

## Gulp 怎么工作？

- 入口: `gulpfile.js` 用代码定义任务, 而不是配置对象;
- 管道: `gulp.src().pipe(plugin()).pipe(gulp.dest())` 串联处理;
- 流: 基于 Node 流与 vinyl 虚拟文件, 中间结果留在内存;
- 组合: v4 起提供 `series` 与 `parallel` 表达串行和并行;
- 优势: 减少磁盘往返, 任务可编程, 适合复杂资产管线;
- 劣势: 流式错误栈难读, 插件质量参差, 调试成本更高;

```js
const { src, dest, series } = require('gulp');
const uglify = require('gulp-uglify');

function scripts() {
  return src('src/**/*.js').pipe(uglify()).pipe(dest('dist'));
}

exports.default = series(scripts);
```

## 两者如何对比？

| 维度 | Grunt | Gulp |
| --- | --- | --- |
| 组织方式 | 配置对象 | 代码与流 |
| 中间产物 | 多数落盘 | 内存传递 |
| 速度 | 文件多时慢 | 通常更快 |
| 可读性 | 声明式, 一眼看懂 | 需要读懂流与异步 |
| 复杂流程 | 需拆多个任务 | 可用函数与条件组合 |
| 生态 | 早期插件多, 维护少 | 插件多, 部分已停更 |

- 共同点: 都只负责文件级转换, 不理解模块依赖图;
- 共同点: 都靠插件拼装, 没有内置的代码分割与 tree shaking;

## 为什么现在少见了？

- 打包器接管: webpack、Vite 直接从入口解析依赖图, 不需要手工列文件;
- 脚本够用: `package.json` 的 scripts 加少量 CLI 就能完成常见任务;
- 维护成本: 插件长期不更新, Node 版本升级后容易报错;
- 仍适用的场景: 图片压缩、字体子集化等与模块无关的资产管线;
- 选择: 新项目优先用打包器内置能力, 确需文件流水线再引入 Gulp;
