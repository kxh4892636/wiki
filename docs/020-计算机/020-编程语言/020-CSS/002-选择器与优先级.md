# CSS 选择器优先级是怎样计算的？

## 常见问题

- CSS 的选择器优先级是怎样？

## 概念索引

- 选择器: 描述元素匹配模式的表达式;
- 特异性: 选择器的权重三元组;
- 层叠顺序: 规则冲突时逐级判定的链条;
- !important: 把声明抬到对应来源的最高档;
- @layer: 按层名声明先后决定谁优先;
- :is() 与 :where(): 前者取最高参数, 后者权重清零, 与层叠顺序配合才能算出真正生效的规则;

## 选择器有哪些类型？

| 类型 | 写法 | 匹配对象 |
| --- | --- | --- |
| 元素 | `a` | 指定标签 |
| 类 | `.item` | 含该 class 的元素 |
| ID | `#app` | 指定 id 的元素 |
| 属性 | `[href^="https"]` | 属性满足条件的元素 |
| 伪类 | `:hover` | 处于某状态或位置 |
| 伪元素 | `::before` | 元素的某部分或生成的盒子 |
| 后代 | `.nav a` | 所有后代 |
| 子代 | `.nav > a` | 直接子元素 |
| 相邻兄弟 | `h2 + p` | 紧跟其后的同级元素 |
| 通用兄弟 | `h2 ~ p` | 之后的所有同级元素 |
| 分组 | `h1, .title` | 任一匹配即命中 |

- 读取方向: 浏览器从右向左匹配, 先找候选元素再验证祖先;
- 影响: 右侧越具体越省事, `.nav > a` 比 `a[href]` 更容易命中;
- 兼容: `:has()` 需要较新的浏览器, 老项目要留降级;

## 特异性怎么计算？

- 三元组 `(A, B, C)`: A 数 ID, B 数类/属性/伪类, C 数元素/伪元素;
- 逐位比较: 先比 A, 相同再比 B, 再比 C, 不做进位;
- 不加权: 通用选择器 `*`、组合符 `>` `+` `~`、空格都是 0;
- 内联样式: 相当于 `(1, 0, 0, 0)`, 普通选择器赢不了它;
- `!important`: 不参与三元组, 直接把声明抬到更高的一档;

| 选择器 | 特异性 |
| --- | --- |
| `*` | (0, 0, 0) |
| `li` | (0, 0, 1) |
| `ul li` | (0, 0, 2) |
| `.nav .item` | (0, 1, 0) |
| `a:hover` | (0, 1, 1) |
| `#app .item` | (1, 1, 0) |
| `style="color: red"` | (1, 0, 0, 0) |

```css
/* 特异性相同, 后写的生效 */
.item { color: blue; }
.item { color: red; } /* 实际生效 */
```

### 两个常见误解是怎样的？

- 11 个类也压不过 1 个 ID, 因为按位比较不进位;
- 易错点: `[type="text"]` 算类, `::first-line` 算元素;

## 特异性相同时按什么决定？

- 判定链: 来源与重要性 → 层叠层 → 特异性 → 出现顺序;
- 来源: 浏览器默认样式最弱, 作者样式最强;
- `!important`: 反转来源顺序, 作者 important 最弱;
- `@layer`: 普通声明里未分层优先, 后声明的层优先;
- 出现顺序: 前面全相同, 后出现的覆盖先出现的;

```css
@layer base, theme;
@layer theme { .btn { color: blue; } } /* 后声明的层 */
.btn { color: red; } /* 未分层, 反而赢 */
```

- 结论: "优先级" 只在同源同层之间才靠特异性比较;

## :is() :not() :where() 如何影响权重？

- `:is()`: 取括号内特异性最高的那个参数;
- `:not()`: 同样取最高参数, 括号本身不计权;
- `:where()`: 整个括号权重为 0, 适合写底层重置;
- `:has()`: 取最高参数, 匹配成本更高, 慎用于大范围;
- 实战: 基础样式用 `:where()`, 业务覆盖用一个类就够了;

```css
:where(.card) .title { color: gray; } /* (0, 1, 0) */
.card .title { color: black; }        /* (0, 2, 0), 稳定覆盖 */
```

## 写选择器有哪些坑？

- 少用 ID: 一旦用 ID, 业务只能靠 `!important` 覆盖;
- 层级别太深: `#app .list li a` 难覆盖, 匹配也慢;
- 加类不加标签: `.nav-link` 比 `.nav a` 稳, 换标签不用改样式;
- 工具类: 原子类都停在 (0, 1, 0), 覆盖顺序靠书写顺序;
- 排查: DevTools 里被划掉的声明, 就是输在特异性或顺序上;
- 规范: 见 [Specificity](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_cascade/Specificity);
