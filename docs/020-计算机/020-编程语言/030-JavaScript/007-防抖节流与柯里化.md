# 防抖、节流与柯里化分别解决什么问题, 代码怎么写?

## 常见问题

- 简述 Javascript 中的防抖与节流的原理并尝试实现
- 简述 Javascript 的柯里化与逆柯里化

## 概念索引

- 防抖: 停下来之后才执行一次;
- 节流: 固定周期内最多执行一次;
- 定时器: 防抖靠不断重置它, 节流靠它补齐末次调用;
- 闭包: 两种实现都靠它保存定时器与最后一次的参数;
- 柯里化: 把多参数函数变成逐次收参的函数链;
- 逆柯里化: 把逐次收参的形式还原成一次传全;

## 防抖在等什么?

- 定义: 调用后等 delay 毫秒, 期间再被调用就重新计时;
- 效果: 连续触发只在静默一段之后执行一次;
- 场景: 搜索联想、窗口 resize 结束、输入框校验;
- 关键: 每次进入先清掉上一次的定时器;

```js
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);        // 清掉上一次, 重新计时
    timer = setTimeout(() => {
      timer = null;
      fn.apply(this, args);     // 用调用时的 this 与参数
    }, delay);
  };
}
```

- 边界: 组件销毁前要能取消, 否则回调可能在卸载后触发;
- 增强: 常补一个 cancel() 清定时器, 或 immediate 选项让首次立刻执行;

```js
function debounce(fn, delay = 300, immediate = false) {
  let timer = null;
  const debounced = function (...args) {
    const callNow = immediate && timer === null; // 只有首次为真
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (!immediate) fn.apply(this, args);
    }, delay);
    if (callNow) fn.apply(this, args);
  };
  debounced.cancel = () => { clearTimeout(timer); timer = null; };
  return debounced;
}
```

## 节流在限制什么?

- 定义: 连续触发时, 每 ms 毫秒最多执行一次;
- 效果: 把高频事件压成稳定频率, 全程都有响应;
- 场景: 滚动加载、鼠标移动、拖拽、按钮防连点;
- 两种实现: 时间戳版比上次执行时间, 定时器版靠冷却开关;

```js
function throttle(fn, ms = 200) {
  let frozen = false;        // 冷却中
  let savedArgs, savedThis;
  return function wrapper(...args) {
    if (frozen) {            // 冷却期只记住最后一次
      savedArgs = args;
      savedThis = this;
      return;
    }
    frozen = true;
    fn.apply(this, args);    // 首次立即执行
    setTimeout(() => {
      frozen = false;
      if (savedArgs) wrapper.apply(savedThis, savedArgs); // 补发末次
      savedArgs = savedThis = null;
    }, ms);
  };
}
```

- 首尾都执行: 这版保证第一次立刻跑, 冷却期内的最后一次也会补跑;
- 只保首次: 去掉补发逻辑, 冷却期内的调用直接丢弃;
- 对比: 节流在触发过程中也会执行, 防抖只在停下来之后执行;

## 柯里化与偏函数是什么关系?

- 柯里化: 把 `f(a, b, c)` 变成 `f(a)(b)(c)` 的调用形式;
- 只变换: 柯里化本身不执行函数, 只做形式转换;
- 偏函数: 已经固定了部分参数的函数, 是柯里化的中间产物;
- 用途: 预置环境参数, 批量生产语义更窄的短函数;

```js
const curry = (fn) =>
  function curried(...args) {
    return args.length >= fn.length
      ? fn.apply(this, args)                                  // 参数够了, 执行
      : (...rest) => curried.apply(this, args.concat(rest));   // 不够继续收
  };

const sum = (a, b, c) => a + b + c;
const curried = curry(sum);
curried(1, 2, 3); // 6
curried(1)(2, 3); // 6
curried(1)(2)(3); // 6
```

- 判据: 收到参数个数达到 `fn.length` 就执行, 否则返回新函数;
- 边界: `(...args)` 写法的函数 length 是 0, 会被立即执行, 不能这样柯里化;
- this: 用 apply 透传, 方法被柯里化后 this 依然正确;

## 逆柯里化怎么做?

- 定义: 把逐次收参的形式还原成一次传全, 也叫 uncurry;
- 常见用法: 让内建方法能作用到任意对象上, 类似 `slice.call` 的思路;
- 实现: 先收函数, 再收目标对象与参数, 最后 apply 一次;

```js
const uncurry = (fn) => (target, ...args) => fn.apply(target, args);

const push = uncurry(Array.prototype.push);
const arr = [];
push(arr, 1); // arr 变成 [1]
push(arr, 2); // arr 变成 [1, 2]
```

- 另一口径: 把 `f(a)(b)(c)` 还原成 `f(a, b, c)`, 做法是收集参数后一次性 apply;
- 取舍: 项目里主要用于借用内建方法处理类数组与字符串;
