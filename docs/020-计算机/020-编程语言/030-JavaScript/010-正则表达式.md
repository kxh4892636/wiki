# 手机号正则怎么写, /w 又是什么意思?

## 常见问题

- 实现匹配手机号的正则表达式
- 正则表达式 /w 是什么意思？

## 概念索引

- 正则字面量: 用两个斜杠包住模式的写法;
- 元字符: 带特殊含义的字符, 要匹配它本身必须转义;
- 字符类: 如 `\w` 与 `\d`, 一次只消费一个字符;
- 量词: 声明前面的元素出现几次;
- 锚点: 把匹配钉在字符串首尾的零宽断言;
- 转义: 把元字符还原成字面意思的操作, 也是 /w 失效的原因;

## 中国大陆手机号的规则是什么?

- 长度: 固定 11 位数字;
- 首位: 固定是 1;
- 第二位: 3 到 9, 写成 `1[3-9]`;
- 后面: 再跟 9 位任意数字;
- 覆盖: 除了 10、11、12 开头的号段之外全部命中;

## 手机号正则怎么写?

- 严格版: `/^1[3-9]\d{9}$/`, 只认纯 11 位数字;
- 锚点作用: 首尾的 `^` 与 `$` 保证整串匹配, 多一个字符都不行;
- 分组版: `/^1(3|4|5|6|7|8|9)\d{9}$/`, 与前一种等价但更啰嗦;
- 宽松版: 允许国家码与分隔符, 先清洗再用严格版校验;

```js
const re = /^1[3-9]\d{9}$/;
re.test("13812345678");  // true
re.test("12812345678");  // false; 第二位不在 3 到 9
re.test("138123456789"); // false; 多了一位, 被 $ 拦住

const intl = /^(\+?86[- ]?)?1[3-9]\d([- ]?\d{4}){2}$/;
intl.test("+86 138-1234-5678"); // true
"+86 138-1234-5678".replace(/\D/g, ""); // "8613812345678"
```

- 现实提醒: 号段会扩容, 校验过严会把新号段判成非法, 应放宽到这个粒度为止;

## \w 匹配什么?

- 定义: 单词字符, 等价于 `[A-Za-z0-9_]`;
- 范围: 只含拉丁字母、数字与下划线, 不含汉字与西里尔文;
- 补集: `\W` 是它的反面, 匹配非单词字符;
- 近亲: `\d` 是数字, `\s` 是空白, `.` 是任意字符且默认不含换行;

```js
"a_1".match(/\w+/)[0];  // "a_1"
"你好".match(/\w/);     // null; 汉字不算单词字符
"你好".match(/\W/g);    // ["你", "好"]
"a b".match(/\w/g);     // ["a", "b"]; 空格被排除
```

- 词边界: `\b` 也是按 `\w` 界定的, 所以对汉字无效;

## 为什么 /w 匹配不到 w?

- 事实: `/w/` 里的 w 是普通字母, 只匹配字符 w 本身;
- 对比: `/\w/` 的反斜杠把 w 变成字符类, 才能匹配任意单词字符;
- 来源: 提问里常把 `\w` 写成 "/w", 少了反斜杠, 语义完全不同;
- 写法: 在代码里始终用字面量 `/\w/`, 别通过字符串拼接;

```js
/w/.test("w");    // true; 只认字母 w
/\w/.test("w");   // true
/w/.test("abc");  // false; 没有字母 w 就失败
/\w/.test("abc"); // true
```

## 还有哪些常见坑?

- lastIndex: 带 `g` 或 `y` 的正则有状态, 复用会被上次的匹配位置影响;
- match 返回 null: 没有命中时是 null 而不是空数组, 直接取 length 会报错;
- 双反斜杠: `new RegExp("\\d")` 才是数字, 写 `"\d"` 会退化成字母 d;
- 元字符: `. + * ? ( ) [ ] { } ^ $ |` 要匹配字面意思都得加反斜杠;
- 四字节字符: emoji 等需要 `u` 标志, 否则会被当成两个字符处理;

```js
const g = /\d/g;
g.test("1"); // true; lastIndex 变成 1
g.test("1"); // false; 从位置 1 开始找不到
g.lastIndex = 0; // 复用前复位
g.test("1"); // true
```
