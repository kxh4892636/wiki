# var、let、const 与作用域、变量提升是什么关系?

## 常见问题

- const, let, var 关键字有什么区别？
- 简述 var let 的区别以及作用域
- 什么是 JavaScript 的变量提升？有什么作用？
- JavaScript 中的严格模式是什么，有什么作用？

## 概念索引

- 作用域: 标识符能被访问到的词法范围;
- 函数作用域: var 的边界是最近的函数;
- 块级作用域: let 与 const 的边界是最近的一个代码块;
- 变量提升: 进入作用域时先把声明登记进环境;
- 暂时性死区: 已登记但未初始化, 访问就抛错的区间;
- 严格模式: 把一批静默失败改成直接报错, 与提升是两套独立开关;

## const、let、var 有什么区别?

| 项 | var | let | const |
| --- | --- | --- | --- |
| 作用域 | 函数 | 块 | 块 |
| 提升 | 提升并初始化为 undefined | 提升但不初始化 | 同 let |
| 重复声明 | 允许 | 报错 | 报错 |
| 必须初始化 | 否 | 否 | 是 |
| 重新赋值 | 可以 | 可以 | 不可以 |
| 挂到 window | 是 | 否 | 否 |

- 共同点: 三者都只是声明, 值可以是任意类型;
- const 的限制: 绑定不能换, 但对象内部照样能改;
- 顶层差异: var 在浏览器里成为 window 的属性, let 与 const 不会;

```js
const user = { name: "a" };
user.name = "b"; // 允许; 改的是对象内容
user = {};       // TypeError; 改的是绑定

var v = 1;
window.v; // 1
let l = 1;
window.l; // undefined
```

## 变量提升到底提升了什么?

- 时机: 进入函数或脚本时先建环境, 把声明登记进去, 早于任何一行执行;
- var: 登记时顺手初始化为 undefined, 所以声明前读到的是 undefined;
- 函数声明: 整个函数体一起提升, 声明位置之前就能调用;
- let 与 const: 只登记不初始化, 初始化语句之前访问抛 ReferenceError;
- 只提升声明: `var a = 1` 拆成顶部声明与原地赋值两步, 赋值不动;
- 死分支也算: `if (false) { var x }` 里的 x 同样被提升;

```js
console.log(a); // undefined
var a = 1;

console.log(b); // ReferenceError; 暂时性死区
let b = 1;

f(); // 正常执行; 函数声明整份提升
function f() {}
```

- 同名冲突: 函数声明先于同名 var 生效, 但后面的赋值会覆盖它;

## var 与 let 在循环里差在哪?

- var: 整个循环共用一个绑定, 回调拿到的是循环结束后的值;
- let: 每轮迭代新建绑定, 上一轮的值被复制进新一轮;
- 结果: 定时器回调输出 3 3 3 与 0 1 2 的经典差异;
- 迁移: 老代码用立即执行函数造作用域, 新代码直接换 let;

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));  // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j));  // 0 1 2
```

## 作用域链如何查找标识符?

- 三类作用域: 全局、函数、块级, 各自对应一个词法环境;
- 连接方式: 每个环境用 outer 指针指向外层, 串成一条链;
- 查找: 从当前环境起, 先查词法环境再查变量环境, 逐级向外;
- 终点: 到全局仍找不到, 读取时抛 ReferenceError;
- 方向: 只能由内向外, 外层永远看不到内层的变量;

- 决定因素: 声明写在哪里, 与函数在哪里被调用无关;

## 严格模式改变了什么?

- 开启: 在脚本或函数的第一行写 `"use strict"`;
- 赋值: 给未声明的名字赋值抛 ReferenceError, 不再偷偷造全局变量;
- 语法: 禁止 with, 禁止形参重名, 禁止八进制字面量;
- this: 裸调用的普通函数里 this 是 undefined, 不再是全局对象;
- arguments: 不再与形参联动, 改形参 arguments 不跟着变;
- 静默失败: 写只读属性、删不可删属性, 从无反应变成抛 TypeError;
