# 定时器为什么不准, 脚本异步加载有哪些方式？

## 常见问题

- 简述 setTimeout 的实现原理
- 异步设定的时间准吗？不准的话怎么解决？
- async 和 defer 有什么区别？
- 简述异步加载的几种方式

## 概念索引

- 计时器: 浏览器或 Node 里独立于主线程的计时设施;
- 最小延迟: 嵌套调用时被抬高的延迟下限;
- 宏任务队列: 定时器回调排队等待执行的位置;
- 漂移: 每次回调耗时累积成的误差;
- defer 与 async: 前者解析完成后保序执行, 后者下载完就执行;
- 动态加载: 运行时插入标签或 import(), 由代码掌控时机;

## setTimeout 的实现原理是什么？

- 登记: 调用时把回调与到期时间交给计时线程, 主线程立即拿到 ID;
- 到期: 计时线程到点把回调推进宏任务队列, 不直接执行;
- 执行: 主线程空了才取出来跑, 所以 `0` 也不是立即执行;
- 结构: 引擎内部按到期时间维护最小堆, 每次取堆顶最快到期的任务;
- 取消: `clearTimeout(id)` 只是把任务标记失效, 已入队的也会跳过;

```js
const id = setTimeout(() => console.log("late"), 1000);
clearTimeout(id); // 到期前取消, 回调不会再执行
```

- 返回值: 浏览器里是数字, Node 里是 Timeout 对象, 不要跨环境假设;

## 定时为什么不准？

| 原因 | 说明 | 表现 |
| --- | --- | --- |
| 主线程阻塞 | 回调要等当前任务与微任务跑完 | 实际延迟远大于设定值 |
| 最小延迟 | 嵌套超过 5 层后最小 4ms | 大量 `0` 延迟被抬高 |
| 后台节流 | 隐藏标签页的计时器被降频 | 后台任务几乎停摆 |
| 系统休眠 | 挂起期间计时不推进 | 唤醒后集中补跑 |
| 计时精度 | 计时线程本身有毫秒级误差 | 短间隔抖动明显 |

- 结论: `delay` 是"最早执行时间", 不是"准时执行时间";
- `setInterval` 更糟: 回调耗时超过间隔时会跳帧或堆积;
- 需要严格间隔: 用 `setTimeout` 递归, 每次按下一次到期时间重算;

## 怎么让定时更准？

- 递归替代: 用 `setTimeout` 自调用, 每轮结束后再排下一次;
- 时间戳校正: 记录起点, 用"目标时刻减当前时刻"作为新延迟;
- 动画改用帧: `requestAnimationFrame` 与刷新率对齐, 后台自动暂停;
- 高精度读数: 用 `performance.now()`, 不受系统时间被调整的影响;
- 长任务分片: 大任务拆小块, 避免阻塞后续所有回调;

```js
const tick = (fn, interval) => {
  const start = performance.now();
  let count = 0;
  const loop = () => {
    count++;
    const drift = performance.now() - start - count * interval;
    fn();
    setTimeout(loop, Math.max(0, interval - drift)); // 扣掉累计漂移
  };
  setTimeout(loop, interval);
};
```

### 什么时候才需要这么做？

- 适用: 轮播、倒计时这类要求长期不漂移的场景;
- 不适用: 需要精确到毫秒级的实时场景, 浏览器本身不保证;

## async 与 defer 有什么区别？

| 属性 | 阻塞解析 | 执行时机 | 执行顺序 |
| --- | --- | --- | --- |
| 不写 | 是 | 下载完立即执行 | 按文档顺序 |
| `defer` | 否 | HTML 解析完后, `DOMContentLoaded` 前 | 按文档顺序 |
| `async` | 否 | 下载完立即执行, 可能早于解析完成 | 谁先下完谁先跑 |

- 适用范围: 只对外部脚本有效, 行内脚本加这两个属性无效;
- 依赖关系: 有依赖的脚本用 `defer`, 独立的第三方脚本用 `async`;
- 事件: `defer` 保证在 `DOMContentLoaded` 前执行完, `async` 不保证;
- 完成: 两者都在 `load` 事件之前执行完毕;

```html
<script defer src="app.js"></script>
<script async src="analytics.js"></script>
```

- 模块脚本: `type="module"` 默认相当于 `defer`, 且重复引入只执行一次;

## 异步加载脚本有哪几种方式？

| 方式 | 写法 | 特点 |
| --- | --- | --- |
| defer | `script defer src` | 不阻塞解析, 保序 |
| async | `script async src` | 不阻塞解析, 不保序 |
| 动态插入 | `createElement("script")` | 时机可控, 默认等价 async |
| `import()` | `await import("./a.js")` | 按需加载模块, 返回 Promise |
| 预加载 | `link rel="preload" as="script"` | 提前下载, 不执行 |

- 动态插入保序: 设 `script.async = false`, 就按插入顺序执行;
- 加载完成: 监听 `onload` 与 `onerror`, 包装成 Promise 更顺手;
- 预加载与预取: `preload` 提前拉取当前页要用的资源, `prefetch` 拉下一跳要用的;

```js
const loadScript = (src) =>
  new Promise((resolve, reject) => {
    const s = document.createElement("script");
    s.src = src;
    s.async = false; // 按插入顺序执行
    s.onload = () => resolve(src);
    s.onerror = () => reject(new Error("load failed: " + src));
    document.head.append(s);
  });
```

- 取舍: 首屏关键脚本用 `defer` 或模块, 统计类用 `async`, 大模块用 `import()` 懒加载;
