# JavaScript 的垃圾回收怎么做, Map 与 WeakMap 差在哪?

## 常见问题

- 简述 JavaScript 垃圾回收的原理
- 简述浏览器的垃圾回收机制
- 简述 weakMap 与 Map 的区别

## 概念索引

- 可达性: 从根出发还走得到的对象才算活着;
- 根集合: 全局对象、调用栈上的局部变量、闭包环境;
- 新生代: 存活时间短的对象, 用复制式算法回收;
- 老生代: 熬过多次回收的对象, 用标记清扫与整理;
- 弱引用: 不阻止对象被回收的引用, 是 WeakMap 的基础;
- WeakMap: 键为弱引用的映射, 键被回收时条目自动消失;

## 垃圾回收在判断什么?

- 目标: 自动回收不再使用的内存, 调用方不必手动释放;
- 判据: 从根集合出发做可达性分析, 走不到的对象即垃圾;
- 根集合: 全局对象、当前调用栈、仍在被引用的闭包环境;
- 好处: 循环引用也能回收, 因为判定看可达性而不是引用计数;

## 为什么要分新生代与老生代?

- 依据: 多数对象很快死掉, 少数活很久, 分代能降低扫描成本;
- 新生代: 空间小, 回收频繁, 每次只处理少量存活对象, 很快;
- 晋升: 存活过若干次回收的对象被移到老生代;
- 老生代: 空间大, 回收次数少, 单次耗时更长;

## 三种回收算法分别是什么?

| 算法 | 过程 | 用在哪 |
| --- | --- | --- |
| 停止-复制 | 存活对象复制到另一半空间, 再交换角色 | 新生代 |
| 标记-清扫 | 标记存活对象, 清理未标记的 | 老生代 |
| 标记-整理 | 标记后把存活对象挪到一侧, 消除碎片 | 老生代 |

- 停止-复制: 只处理存活对象, 用空间换时间, 需要短暂暂停执行;
- 标记-清扫: 不挪动对象, 快但会留下内存碎片;
- 标记-整理: 挪动对象消除碎片, 代价是搬移开销;

## 循环引用为什么不再是问题?

- 旧口径: 引用计数算法下, 互指的一对对象计数永不归零, 于是泄漏;
- 现代口径: 标记清除从根出发, 不可达的循环引用照样被回收;
- 仍会泄漏: 被全局变量或闭包意外留住的引用解不开, 才算真泄漏;
- 兜底: 确定不用时把引用置空, 不要把意图交给引擎去猜;

```js
const a = {};
const b = {};
a.b = b;
b.a = a;
// 外部不再引用 a 与 b 时, 现代引擎会把它们一起回收
```

## Map 与 WeakMap 有什么区别?

| 项 | Map | WeakMap |
| --- | --- | --- |
| 键类型 | 任意值 | 只能是对象 |
| 引用强度 | 强引用, 键不回收 | 弱引用, 键可回收 |
| 遍历 | 支持 keys、values、entries | 不支持任何遍历 |
| size | 有 | 没有 |
| 用途 | 通用字典、带淘汰的缓存 | 给对象挂私有数据 |

- 弱键: 键对象没有其它引用时会被回收, 对应条目自动消失;
- 无法遍历: 条目数量随回收变化, 迭代没有稳定语义, 所以干脆不提供;
- 可用方法: set、get、has、delete, 就这四个;
- 同理: WeakSet 只能 add、has、delete, 值也必须是对象;

```js
let key = { id: 1 };
const wm = new WeakMap();
wm.set(key, "val");
key = null;   // 对象可被回收, 条目随之消失

let k2 = { id: 2 };
const m = new Map();
m.set(k2, "val");
k2 = null;    // Map 仍强引用该对象, 条目还在
m.size;       // 1
```

## 哪些写法会增加回收压力?

- 全局变量: 常驻内存, 生命周期最长, 能不用就不用;
- 频繁造大对象: 触发更多回收, 而回收要暂停执行, 会掉帧;
- 闭包滥用: 无意中把大对象留在闭包里, 迟迟不释放;
- 删属性: 运行时增删属性会打乱隐藏类, 拖慢对象访问;
- 优化: 复用对象池、缩小变量作用域、创建时定好全部属性;
