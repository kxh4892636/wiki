# Go 的 map 是如何实现的？

## 常见问题

- Golang 是如何实现 Maps 的？

## 概念索引

- 哈希表: 用 key 的哈希定位桶;
- 桶: 每个桶存若干键值对;
- 溢出桶: 桶满后挂接的额外桶;
- 扩容: 装载因子过高时渐进迁移;
- 无序: range 遍历顺序不保证;

## map 的底层结构是什么？

| 结构 | 作用 |
| --- | --- |
| hmap | map 的头部，记录桶数组、长度、哈希种子 |
| bmap | 桶，通常存 8 个键值对 |
| tophash | 每个槽位哈希的高 8 位，快速比较 |
| overflow | 桶满后挂接的溢出桶 |

```go
m := make(map[string]int)
m["go"] = 1
v, ok := m["go"] // ok 区分键不存在与值为零
```

- key 必须可比较，切片、map、函数不能做 key;
- 哈希值决定桶，tophash 先筛选，再比较完整 key;
- 桶内是连续数组，删除只标记空槽，不立即搬移;

## 扩容与迁移如何发生？

- 装载因子过高，或溢出桶过多时触发扩容;
- 扩容分配新桶数组，旧桶逐步迁移;
- 迁移是渐进的，每次读写顺手搬一部分;
- 迁移期间同时存在新旧桶，查找会两边看;
- 扩容不是一次性复制全部元素，避免长暂停;

## 为什么遍历顺序不固定？

- range 从随机桶、随机槽位开始;
- 每次遍历顺序都可能不同;
- 这不是 bug，而是有意的随机化，防止依赖顺序;
- 需要稳定顺序: 先收集 key、排序，再按序读取;

```go
keys := make([]string, 0, len(m))
for k := range m {
    keys = append(keys, k)
}
sort.Strings(keys)
for _, k := range keys {
    fmt.Println(k, m[k])
}
```

## nil map 能做什么？

| 操作 | nil map |
| --- | --- |
| 读取 | 返回零值，安全 |
| 删除 | 空操作，安全 |
| 写入 | panic |
| range | 不迭代，安全 |

- 声明后必须 make 或字面量初始化才能写入;
- 读取不存在的键不会报错，返回零值;
- 用 comma ok 区分“键不存在”和“值恰好为零值”;

## map 并发安全吗？

- 不安全: 并发读写会 data race，运行时可能直接 panic;
- 方案一: Mutex / RWMutex 保护整张 map;
- 方案二: sync.Map，适合读多写少或键集合稳定;
- 方案三: 分片锁，降低单锁竞争;
- 检查: go test -race 只能发现已执行路径上的竞争;
