# Go 的 map 是如何实现的？

## 常见问题

- Golang 是如何实现 Maps 的？

## 概念索引

- 组: 8 个键值槽加 8 字节控制字;
- 控制字: 每槽 1 字节，标记空、墓碑或 7 位指纹;
- 表: 一张完整哈希表，容量是 2 的幂;
- 目录: 用哈希高位选表，让扩容可以分块做;
- 探测: 组里没找到就按三角数跳下一组;
- 墓碑: 删除留下的印记，扩容时才清掉;

## map 的底层结构是什么？

- 使用 Swiss table 实现 Map；

```text
map 头
├─ 元素个数
├─ 哈希种子
└─ 目录指针 ──→ 目录
                 ┌────┬────┬────┐
                 │ 00 │ 01 │ 10 │ ...
                 └─┬──┴─┬──┴─┬──┘
                   ▼    ▼    ▼
                 表0   表0   表1   ← 多个格子可指向同一张表

一张表 = 一堆组，一个组:
┌────────────────────────────────┐
│ 标记 [m0][m1][m2]...[m7]       │ 8 字节
│ 格子  k0/v0  k1/v1 ...  k7/v7  │ 键值内联
└────────────────────────────────┘
```

| 结构 | 干什么 |
| --- | --- |
| map 头 | 记元素数、哈希种子、目录指针 |
| 目录 | 用哈希高位选表，支持增量扩容 |
| 表 | 若干组，容量 2 的幂，最多 1024 槽 |
| 组 | 8 个槽 + 1 个控制字，查找的最小单位 |
| 槽 | 一个键值对，单边超 128 字节改存指针 |

## 一次查找怎么走？

- 算哈希，切三段: 选表、选组、指纹;
- 按探测序列选组: 起点是 `(h >> 7) & (组数 - 1)`;
- 读一组控制字，一次比 8 个槽，得到候选位图;
- 候选逐个比完整 key，命中就返回;
- 组里有空槽就停，说明后面的组不可能有它;

```text
h    = hash(key)
表   = 目录[h >> globalShift]
组   = (h >> 7) & (组数 - 1)          ← 探测起点
候选 = 控制字 xor (指纹重复 8 次) → 位图
```

- 为什么快: 8 个字节一次读完，一条指令筛完 8 格;
- 误判: 7 位只有 128 种值，撞上再比完整 key 兜底;

## 哈希是多少位？

- 宽度: 64 位平台 64 位，32 位平台 32 位;
- 算法: 数值走 memhash，字符串走 strhash，有 AES-NI 走 aeshash;
- 种子: 每张 map 一个随机 hash0，防止构造碰撞拖垮查表;

```text
64 位哈希
┌───────────────┬─────────────────────┬──────────┐
│ 最高几位        中间若干位             低 7 位    │
│ 选表           选组                  指纹 H2    │
└───────────────┴─────────────────────┴──────────┘
```

- 选组: `h >> 7` 丢掉指纹位，再用组数掩码取中段;
- 取指纹: `h & 0x7f` 只留低 7 位，最高位因此为 0，正好表示占用;
- 32 位平台: 高 25 位选组，低 7 位当指纹;

## 控制字怎么编码？

| 值 | 含义 |
| --- | --- |
| `0x80` | 空，探测到它就停 |
| `0xFE` | 墓碑，删过，探测不停 |
| `0??xxxxxxx` | 占用，最高位 0，低 7 位存指纹 |

- 为什么 7 位: 1 个字节要留最高位当空/占用状态位;

## 扩容怎么走？

- 阈值: 装到 7/8 就扩，始终留 1 个空槽当探测终点;
- 表内翻倍: 容量从 2N 扩到 4N，上限 1024 槽;
- 表分裂: 超过 1024 就一拆二，两个新表各 1024 槽;
- 目录翻倍: 表深度追平目录深度时，目录才跟着翻;
- 增量: 一次只重排一张表，不是整张 map 重排;

## 两个深度分别指什么？

- 目录深度: `globalDepth`，目录用哈希最高几位选格，格数 = `1 << globalDepth`;
- 表深度: `localDepth`，这张表认几位前缀，决定它占几个目录格;
- 占格数: `2^(globalDepth − localDepth)`，多个格子指向同一张表;
- 连续: 前缀是连续区间，所以表占的格子也连续;

```text
globalDepth = 2 → 目录 4 格
┌──────┬──────┬──────┬──────┐
│  00  │  01  │  10  │  11  │
└──┬───┴──┬───┴──┬───┴──┬───┘
   ▼      ▼      ▼      ▼
 表 A   表 A   表 B   表 B
  ↑ localDepth 1，占 2 格       ↑ localDepth 2，占 1 格
```

| 目录深度 | 表深度 | 占格数 |
| --- | --- | --- |
| 3 | 1 | 4 |
| 3 | 2 | 2 |
| 3 | 3 | 1 |

- 分裂: 表装满就拆成两张，localDepth 加 1;
- 先翻目录: 只有 localDepth 追平 globalDepth，目录才翻倍;
- 翻倍后: 旧第 i 格变成新第 2i、2i+1 格，指针复制一份;

```text
翻倍前（2 位）        翻倍后（3 位）
00 01      → A       000 001 010 011 → A（4 格）
10 11      → B       100 101         → B0（2 格）
                     110 111         → B1（2 格）
```

## 小 map 有优化吗？

- 8 个元素以内: 整个 map 就一组，没有目录;
- 没有墓碑: 小 map 不做删除标记，槽位直接写;
- 一次分配: 头和组在一起，短命 map 的开销更低;
- 超过 8 个: 才分配目录与表，走常规路径;

## 为什么遍历顺序不固定？

- range 从随机的组、随机的格子开始;
- 每次顺序都可能不同;
- 这不是 bug，是有意随机，防止业务依赖顺序;
- 撞上扩容: 保留旧表引用继续扫，再回新表查值;
- 要稳定顺序: 先收 key 排序，再按序读;

```go
keys := make([]string, 0, len(m))
for k := range m {
    keys = append(keys, k)
}
sort.Strings(keys)
for _, k := range keys {
    fmt.Println(k, m[k])
}
```

## nil map 能做什么？

| 操作 | nil map |
| --- | --- |
| 读取 | 返回零值，安全 |
| 删除 | 空操作，安全 |
| 写入 | panic |
| range | 不迭代，安全 |

- 声明后必须 make 或字面量初始化才能写入;
- 读取不存在的键不报错，返回零值;
- 用 comma ok 区分“键不存在”和“值恰好为零值”;

## map 并发安全吗？

- 不安全: 并发读写会 data race，运行时可能直接 panic;
- 检测: 写时翻转一个标志，撞上就报 fatal;
- 局限: 只是概率检测，不能保证每次都抓得住;
- 方案一: Mutex / RWMutex 保护整张 map;
- 方案二: sync.Map，适合读多写少或键集合稳定;
- 方案三: 分片锁，降低单锁竞争;
- 检查: go test -race 只能发现已执行路径上的竞争;
