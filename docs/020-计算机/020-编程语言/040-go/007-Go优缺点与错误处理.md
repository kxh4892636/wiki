# Go 有哪些优缺点，错误处理有什么优缺点？

## 概念索引

- 简洁: 语法小、工具链统一;
- 并发: goroutine 与 channel;
- 编译: 静态链接、快速构建;
- 错误值: error 是普通返回值;
- 包装: %w、errors.Is、errors.As;

## Go 有哪些优点？

| 优点 | 说明 |
| --- | --- |
| 语法简单 | 关键字少，团队上手快 |
| 编译快 | 依赖分析简单，构建与部署快 |
| 并发内建 | goroutine、channel、调度器 |
| 部署简单 | 静态链接，单文件二进制 |
| 工具链统一 | go fmt、test、vet、mod 开箱即用 |
| GC | 自动内存管理，降低心智负担 |

## Go 有哪些缺点？

| 缺点 | 说明 |
| --- | --- |
| 错误处理冗长 | if err != nil 重复出现 |
| 表达力有限 | 缺少异常、注解、宏等机制 |
| 泛型较晚 | 复杂抽象不如其它语言自然 |
| nil 与零值陷阱 | nil map 写入、nil 接口等易踩 |
| 运行时细节多 | GC、调度、逃逸需要理解 |
| 生态偏服务端 | GUI、数据科学等不如其它语言 |

## Go 的错误处理怎么做？

```go
func div(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("divide by zero")
    }
    return a / b, nil
}

n, err := div(10, 0)
if err != nil {
    return fmt.Errorf("div: %w", err)
}
fmt.Println(n)
```

- error 是最后一个返回值，nil 表示成功;
- 调用方先检查 err，再使用结果;
- 需要上下文时用 %w 包装，保留错误链;
- 判断用 errors.Is，提取类型用 errors.As;

## 错误处理有哪些优缺点？

| 优点 | 缺点 |
| --- | --- |
| 控制流显式，错误不会被静默吞掉 | 样板代码多，容易重复 |
| 包装后保留上下文与原因 | 层层包装可能丢失原始类型 |
| errors.Is/As 支持结构化判断 | 需要约定错误类型与哨兵值 |
| 没有异常栈展开成本 | panic/recover 不适合常规错误 |

## 什么时候用 panic？

- 程序无法继续: 配置缺失、不可恢复的不变量破坏;
- 库边界: 把 panic 转成 error 再返回;
- 常规错误: 用 error，不用 panic;
- recover 只应放在明确的边界，不要用它做普通控制流;
