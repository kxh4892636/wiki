# Go 的 GMP 模型与 goroutine 调度是怎样的？

## 常见问题

- 简单介绍 GMP 模型以及该模型的优点
- 简述 Goroutine 的调度流程
- 协程与进程，线程的区别是什么？协程有什么优势？
- Golang 的一个协程能保证绑定在一个内核线程上吗？
- Golang 的协程可以自己主动让出 CPU 吗？
- 简述 Golang 的伪抢占式调度
- 什么是 goroutine 泄漏
- groutinue 什么时候会被挂起？

## 概念索引

- G: goroutine，用户态轻量执行单元;
- M: 操作系统线程，真正执行代码的载体;
- P: 处理器上下文，持有运行队列与调度资源;
- 调度器: 把 G 分配给 M 执行;
- 本地队列: 每 P 一个环形队列，存放待跑的 G;
- 偷取: 空闲 P 从其它 P 分走一半 G;
- 抢占: 长任务让出 CPU 的机制;
- 挂起: G 等待 channel、锁、IO 等资源;

## GMP 各角色负责什么？

| 角色 | 含义 | 作用 |
| --- | --- | --- |
| G | goroutine | 保存栈、状态与待执行函数 |
| M | OS 线程 | 真正被内核调度的执行线程 |
| P | 处理器上下文 | 持有本地运行队列、分配缓存等 |
| 全局队列 | 所有 P 共享 | 存放暂时没有归属的 G |

- GOMAXPROCS 决定 P 的数量，默认等于 CPU 核数;
- M 必须绑定 P 才能执行 Go 代码;
- G 阻塞时，M 可以释放 P 给其他 M 使用;
- M 按需创建，上限 10000，空闲后退回休眠;

## 为什么要有 P？

- 无 P 时: 每个 G 直接挂到 M 上，所有 G 抢同一把调度锁;
- 有 P 时: G 放本地队列，绝大多数入队出队无锁;
- 资源隔离: P 持有内存分配缓存，避免分配也抢全局锁;
- 调度代价: 切换只在用户态改状态，不进内核;
- GOMAXPROCS: 真正的并行度是 P 数，不是 G 数;

## 一次调度如何发生？

```text
go f()
  ↓
创建 G，放本 P 的 runnext 槽，满了再进本地队列
  ↓
M 绑定 P，从 runnext / 本地队列取 G
  ↓
执行 G；阻塞、系统调用、时间片用完时切换
  ↓
本地队列空时，从全局队列或其它 P 偷取
```

| 场景 | 调度动作 |
| --- | --- |
| 本地队列为空 | 从全局队列取，或 work stealing |
| G 阻塞在 channel/锁 | 让出 P，M 去执行其它 G |
| 系统调用阻塞 | P 被移交，M 阻塞在 syscall |
| 网络 IO 等待 | G 挂到 netpoller，M 直接换 G |
| 长循环不让出 | 异步抢占信号打断 |

## 系统调用阻塞时发生了什么？

- 进入: G 调 entersyscall，P 转 _Psyscall，M 与 P 解绑;
- 卡住: 线程在内核里睡，跑不了任何 Go 代码，也带不走 P;
- 收回: sysmon 发现 M 停留超 20µs，把 P 交给空闲 M 或新建 M;
- 返回: G 转 _Grunnable 入队，原 M 抢到 P 才接着跑，抢不到就休眠;
- 例外: socket 是非阻塞的，走 netpoller，只挂起 G 不卡线程;
- cgo: 调用期间同样交出 P，与系统调用同一路径;

```go
go func() { os.Read(fd, buf) }() // 文件 IO 卡住线程，触发 handoff
go func() { conn.Read(buf) }()   // 网络 IO 走 netpoller，线程不卡
```

- 代价: 大量阻塞调用会撑大线程数，逼近 10000 上限就报错;

## 长循环不让出会怎样？

- 场景: 紧凑循环里没有函数调用，到达不了任何检查点;
- 协作抢占: 只在函数入口的栈检查处响应，循环体内部不检查;
- 后果: 同 P 上的 G 排队饿死，GC 等不到安全点，整个程序卡住;
- 异步抢占: Go 1.14 起 sysmon 对连续跑超 10ms 的 G 发 SIGURG;
- 信号处理: 把 G 停在安全点挂起，调度器换下一个 G 上 P;
- Windows: 用 SuspendThread 代替信号，效果相同;
- 兜底: 循环体里调 runtime.Gosched 或普通函数，主动还 P;

```go
for { sum += i }        // 无调用，只能等 10ms 的异步抢占
for { sum += f(i) }     // 有调用，函数入口就能被抢占
```

## goroutine 与进程、线程有什么区别？

| 项 | 进程 | 线程 | goroutine |
| --- | --- | --- | --- |
| 地址空间 | 独立 | 共享 | 共享 |
| 栈大小 | 较大 | 较大 | 初始约 2KB，可增长 |
| 切换成本 | 高 | 中 | 低，用户态调度 |
| 调度者 | 内核 | 内核 | Go runtime |
| 数量级 | 少 | 较少 | 可达十万级 |

- 协程优势: 创建便宜、切换便宜、适合高并发 IO;
- 代价: 共享内存仍需同步，goroutine 泄漏要自己管理;

## goroutine 会绑定内核线程吗？

- 默认不绑定: G 与 M 是 M:N 调度，G 可在不同 M 上运行;
- 例外: `runtime.LockOSThread` 把当前 goroutine 绑定到当前线程;
- 适用: cgo 回调、图形库、需要线程局部状态的场景;
- 注意: 绑定后要及时 `UnlockOSThread`，否则线程无法复用;

## goroutine 能主动让出 CPU 吗？

- 主动: `runtime.Gosched()` 让出当前 P，重新排队;
- 隐式: channel 阻塞、锁等待、sleep 都会让出;
- 抢占: Go 1.14 起基于信号异步抢占，机制见上一节;
- 伪抢占: 1.14 前只在函数调用等安全点检查，长循环可能延迟抢占;

## 什么时候会挂起或泄漏？

| 场景 | 行为 |
| --- | --- |
| 无缓冲 channel 等接收 | G 挂起，等待配对操作 |
| 加锁失败 | G 挂起，等待锁释放 |
| 网络/文件 IO | G 挂起，由 netpoller 唤醒 |
| 永久等待 | 没有人发送/关闭/释放，形成泄漏 |

```go
func leak() {
    ch := make(chan int)
    go func() {
        <-ch // 永远等不到发送者
    }()
}
```

- 防泄漏: 明确退出条件，使用 context、超时或关闭信号;
- 排查: `pprof` 的 goroutine profile 看阻塞栈;
