# React 的渲染流程是什么？

## 常见问题

- 简述 React 的渲染流程

## 概念索引

- 触发: 首次挂载或状态更新;
- 渲染: React 调用组件，计算新 UI;
- 协调: 对比新旧树，找出最小变更;
- 提交: 把变更写入 DOM;
- 绘制: 浏览器画像素;
- 副作用: 布局 Effect 与被动 Effect 在提交后运行;

## 一次更新经历哪些阶段？

```text
触发 render
    ↓
调用组件，计算新 UI
    ↓
协调新旧树，标记变更
    ↓
提交 DOM 变更
    ↓
浏览器绘制
    ↓
useEffect / useLayoutEffect
```

| 阶段 | 做什么 | 能否中断 |
| --- | --- | --- |
| 触发 | root.render 或 state 更新入队 | 否 |
| 渲染 | 调用组件，递归计算 | 并发模式可中断 |
| 协调 | 对比元素类型与 key | 是 |
| 提交 | 插入、更新、删除 DOM | 否 |
| 绘制 | 浏览器布局与绘制 | 否 |

## 渲染阶段与提交阶段有什么区别？

| 项 | 渲染阶段 | 提交阶段 |
| --- | --- | --- |
| 工作 | 计算 JSX、对比树 | 改 DOM、附加 ref |
| 副作用 | 禁止 | 允许 |
| 可重做 | 可以 | 不可以 |
| 典型 API | 组件函数、render | useLayoutEffect、useEffect |

```jsx
function App() {
  return <h1>Hello</h1>;
}

const root = createRoot(document.getElementById("root"));
root.render(<App />);
```

## 重新渲染会重建 DOM 吗？

- 同类型、同位置: 复用 DOM 与 state;
- 类型变化: 卸载旧树，创建新树;
- key 变化: 视为新条目，重置 state;
- 输出相同: 可能不产生 DOM 修改;

- 渲染次数不等于 DOM 重建次数;
- 列表 key 必须稳定唯一;
- 父组件更新默认会递归渲染子树;

## 如何优化渲染？

| 手段 | 作用 | 注意 |
| --- | --- | --- |
| Profiler | 找昂贵子树 | 先测量 |
| 局部 state | 缩小重渲染范围 | 别过早提升 |
| memo | props 未变跳过渲染 | 比较有成本 |
| useMemo / useCallback | 缓存值与函数 | 依赖要正确 |
| useTransition | 标记非紧急更新 | 保持输入响应 |
| React Compiler | 自动记忆化 | 遵守 Hook 规则 |
