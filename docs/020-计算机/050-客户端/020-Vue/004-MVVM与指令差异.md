# MVC 与 MVVM 有什么区别，v-if 和 v-show 怎么选？

## 常见问题

- MVC 模型和 MVVM 模型的区别
- V-show 和 V-if 有什么区别

## 概念索引

- MVC: 模型、视图、控制器三层分工;
- Controller: 接收输入, 调模型, 选视图;
- MVVM: 视图与视图模型双向绑定;
- ViewModel: 把模型数据转成视图可直接用的状态;
- 数据驱动: 只改数据, 视图由框架同步;
- v-if: 条件不成立就销毁节点;
- v-show: 只切换 display 样式;

## MVC 的三层各管什么？

- Model: 数据与业务规则, 不关心界面;
- View: 只负责展示, 通常是被动的;
- Controller: 接收用户输入, 更新模型, 再选视图;
- 流向: 用户操作到 Controller, 到 Model, 再到 View;
- 后端 MVC: Controller 处理请求, 直接返回渲染好的页面;
- 痛点: 视图逻辑与控制器逻辑容易混在一起;

## MVVM 比 MVC 多了什么？

| 项 | MVC | MVVM |
| --- | --- | --- |
| 中间层 | Controller 处理输入 | ViewModel 做数据映射 |
| 通信方向 | 单向为主 | 视图与数据双向 |
| 同步方式 | 手动更新视图 | 框架自动同步 |
| 视图状态 | 常存在 DOM 里 | 收敛到 ViewModel |
| 测试 | 依赖视图环境 | ViewModel 可单独单测 |

- ViewModel: 暴露给视图的是可直接渲染的状态与命令;
- 双向: 视图改数据、数据改视图都不用写同步代码;
- 收益: 视图变薄, 状态可测, DOM 操作减少;
- 代价: 双向绑定过多时, 数据流向难追踪;

## Vue 算严格的 MVVM 吗？

- 官方说法: Vue 借鉴 MVVM, 但没有完全遵循;
- 原因: 组件既是视图也承担视图模型的职责;
- 双向: v-model 只是语法糖, 默认仍是单向数据流;
- 结论: 当成数据驱动的组件框架更准确;
- 对比: React 更偏函数式, 用 setState 显式驱动;

## v-if 与 v-show 的差别在哪？

| 项 | v-if | v-show |
| --- | --- | --- |
| 实现 | 销毁与重建 | 切换 display |
| 初始成本 | 条件为假时几乎为零 | 总要渲染一次 |
| 切换成本 | 高, 走完整创建挂载 | 低, 只改样式 |
| 生命周期 | 会触发创建与卸载钩子 | 不触发 |
| DOM 是否存在 | 不存在 | 存在 |
| 适用 | 条件少变 | 频繁切换 |

```html
<!-- v-if 为假: 编译成注释占位, 节点不存在 -->
<!-- v-if -->

<!-- v-show 为假: 节点仍在, 只是 display 为 none -->
<div style="display: none">内容</div>
```

- 权限控制: 用 v-if, 不该渲染的代码不要进 DOM;
- 频繁切换: 用 v-show, 如 Tab 面板、折叠区域;
- 首屏不可见: 用 v-show 反而多一次渲染, 不如 v-if;

## 同一元素上能一起用吗？

- Vue 2: v-for 优先级高于 v-if, 会先循环再判断;
- Vue 3: v-if 优先级高于 v-for, 会先求值;
- 风险: 在 v-if 里引用 v-for 的变量会直接报错;
- 建议: 把条件提到外层 template, 或先用 computed 过滤;
- 性能: 模板里少写复杂表达式, 逻辑放 computed;
