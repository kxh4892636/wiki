# 进程和线程有什么区别？

## 常见问题

- 进程和线程之间有什么区别？
- 多线程和多进程的区别是什么？
- 创建线程有多少种方式？
- 线程间有哪些通信方式？
- 为什么进程切换慢，线程切换快？
- 两个线程交替打印一个共享变量

## 概念索引

- 进程: 资源分配的基本单位;
- 线程: CPU 调度的基本单位;
- 地址空间: 进程私有的内存视图;
- 页表: 把虚拟地址翻译成物理地址的表;
- 上下文: 切换现场需要保存的寄存器集合;
- 竞态: 共享数据被并发访问导致结果不定;
- 条件变量: 用等待队列消除竞态，让交替打印有确定顺序;

## 进程与线程的本质区别是什么？

- 资源: 进程持有地址空间、文件表、信号处理等资源;
- 调度: 线程才是 CPU 调度的实体，进程是资源容器;
- 共享: 同进程线程共享代码段、数据段、堆和打开的文件;
- 私有: 线程只私有寄存器上下文与栈这两样;
- 隔离: 进程间内存隔离，一个进程越界不影响别人;
- 代价: 线程共享内核资源，一个线程崩溃拖垮整个进程;

## 多线程和多进程如何取舍？

| 关注点 | 多进程 | 多线程 |
| --- | --- | --- |
| 隔离性 | 强，故障不扩散 | 弱，共享地址空间 |
| 切换开销 | 大，换页表与 TLB | 小，只换寄存器与栈 |
| 通信 | 需 IPC，要序列化 | 直接读写共享变量 |
| 同步成本 | 低，天然隔离 | 高，必须加锁 |
| 典型用法 | Nginx worker、Chrome 标签页 | 线程池、Java 业务服务 |

- 经验: CPU 密集且要强隔离选多进程，I/O 密集且共享状态多选多线程;
- 折中: 多进程加每进程多线程，如 Nginx 的 master-worker 模型;

## 创建线程有哪几种方式？

- C 库: `pthread_create` 传入函数指针与参数，`pthread_join` 等待，底层走 `clone`;
- 高级语言: C++ `std::thread`、Java `Thread`、Python `threading.Thread`;
- 线程池: 复用线程避免反复创建，如 Java `ThreadPoolExecutor`;
- 协程: 用户态调度，不是内核线程，如 goroutine;

```c
#include <pthread.h>

void *work(void *arg) { return NULL; }

int main(void) {
  pthread_t t;
  pthread_create(&t, NULL, work, NULL);  // 创建
  pthread_join(t, NULL);                 // 等待退出
  return 0;
}
```

- 本质: `clone` 靠标志位决定共享什么，`CLONE_VM` 共享地址空间即线程;
- 边界: 共享地址空间但各自持有文件表，就介于进程与线程之间;

## 线程间如何通信？

- 通道: 线程天然共享地址空间，共享变量就是最直接的通道;
- 同步: 互斥锁保护临界区，条件变量做等待与唤醒;
- 无锁: 原子变量配内存序，适合计数器与标志位;
- 队列: 阻塞队列把通信与同步合成一个原语，生产消费最常用;
- 对比: 用 pipe 在线程间传数据也行，但多走一次内核，比共享变量慢;
- 结论: 线程通信的难点是同步，不是传递;

## 为什么进程切换比线程切换慢？

- 页表: 换进程要换 CR3 指向的页表基址，TLB 随之失效;
- 缓存: 新进程工作集不在 L1/L2 里，冷启动带来大量不命中;
- 共同开销: 两者都要陷入内核保存恢复现场，这部分一样;
- 线程: 同进程线程共用页表，TLB 与缓存仍然有效;
- 量级: 进程切换常在微秒级，线程切换常在几百纳秒级;
- 反例: 跨核线程切换、跨 NUMA 迁移同样会让缓存失效;

## 两个线程如何交替打印？

- 需求: 两个线程按 A、B、A、B 的顺序打印同一个计数器;
- 错误做法: 只用共享标志位自旋，靠运气且忙等烧 CPU;
- 正确做法: 互斥锁加条件变量，把顺序显式写进等待条件;

```cpp
#include <condition_variable>
#include <cstdio>
#include <mutex>
#include <thread>

std::mutex m;
std::condition_variable cv;
int turn = 0;  // 0 打印 A，1 打印 B
const int N = 10;

void run(int id) {
  for (int i = 0; i < N; i++) {
    std::unique_lock<std::mutex> lk(m);
    cv.wait(lk, [id] { return turn == id; });  // 谓词防虚假唤醒
    std::printf("%c", 'A' + id);
    turn = 1 - id;
    cv.notify_all();
  }
}

int main() {
  std::thread a(run, 0), b(run, 1);
  a.join();
  b.join();
}
```

- 要点: 判断条件放进 `wait` 的谓词里，醒来会重新检查;
- 要点: 先改 `turn` 再 `notify`，被唤醒的线程才能看到新状态;
