# malloc 如何分配内存，对象到底在堆还是栈？

## 常见问题

- 简述操作系统中 malloc 的实现原理
- malloc 创建的对象在堆还是栈中？
- 如何调试服务器内存占用过高的问题？

## 概念索引

- 堆: 进程内由分配器管理的可增长区域;
- brk: 直接移动堆顶指针扩展堆;
- mmap: 大块分配走匿名映射;
- chunk: glibc 分配器的内存块单元;
- tcache: 每线程的小块缓存，免加锁;
- 碎片: 空闲内存存在却拼不出所需大小，是常驻内存不降的常见解释;

## malloc 的实现原理是什么？

- 两层: `malloc` 是库函数，底层向内核要内存用 `brk` 或 `mmap`;
- 小块: 默认小于 128 KiB 用 `brk` 抬高堆顶，切分成 chunk 复用;
- 大块: 超过阈值用 `mmap` 单独映射，`free` 时直接还回内核;
- 记录: 每个 chunk 前有头部，记大小与前后块是否空闲的标志位;
- 回收: `free` 一般只放回空闲链表，不一定还给内核，故 RSS 不降;

```c
void *p = malloc(1024);  // brk 扩展堆，切出 chunk
void *q = malloc(1 << 20); // 超过阈值，走 mmap 单独映射
free(p);                 // 放回空闲链表，堆顶未必收缩
free(q);                 // munmap 直接归还
```

## 分配器还有哪些细节？

- 多线程: 多 arena 加每线程 `tcache`，减少锁竞争;
- 阈值: glibc 的 `M_MMAP_THRESHOLD` 默认 128 KiB，会随释放大块动态上调;
- 观察: `mallinfo2` 与 `malloc_stats` 能看已用与空闲的字节数;

## 对象在堆还是栈中？

| 位置 | 分配方式 | 生命周期 | 大小限制 |
| --- | --- | --- | --- |
| 栈 | 函数调用时自动分配 | 随栈帧销毁 | 默认 8 MB 左右 |
| 堆 | `malloc` 或 `new` | 手动释放或 GC | 受虚拟地址与内存限制 |
| 静态区 | 全局与静态变量 | 整个进程 | 编译期确定 |

- 结论: `malloc` 与 `new` 拿到的对象一律在堆上;
- 例外: 编译器可把未逃逸的 `new` 优化掉，但语言语义仍是堆分配;
- 栈对象: 局部变量在栈上，逃逸到堆是多线程共享的前提;
- 判断: 看分配语句，不看类型，栈上也可能放指针指向堆;

## 如何调试内存占用过高？

- 先分层: `VmSize` 是虚拟内存，`VmRSS` 是实际占用的物理页;
- 进程级: `ps -o rss,vsz`、`smem -P <名>` 看谁在涨;
- 细节: `pmap -x <pid>` 与 `/proc/<pid>/smaps` 按段看堆、映射与共享;
- 趋势: `vmstat 1` 看 `si/so` 是否在换页，`free -m` 看可用内存;
- 堆内: `valgrind --tool=massif` 或 `heaptrack` 抓分配调用栈;
- 泄漏: 长时间运行 RSS 单调上涨而业务量不变，基本可判泄漏;

```text
定位顺序: free 看全局 -> ps 找进程 -> smaps 找区段
           -> 抓堆快照比对 -> 回到代码看谁没 free
```

## 内存高时容易误判什么？

- 缓存: page cache 占满内存是正常的，看 `available` 而不是 `free`;
- 成因: 容器未设上限、连接未关、缓存无淘汰、线程栈累积;
- 兜底: `MALLOC_TRIM_THRESHOLD_` 与 `malloc_trim` 可把空闲堆还给内核;
