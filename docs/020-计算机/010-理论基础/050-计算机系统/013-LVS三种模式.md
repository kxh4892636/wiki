# LVS 的 NAT、TUN、DR 三种模式有什么区别？

## 常见问题

- LVS 的 NAT、TUN、DR 原理及区别

## 概念索引

- Director: 负载均衡器, 持有虚拟 IP;
- VIP: 客户端看到的虚拟 IP, 由 director 与真实服务器共同承载;
- Real Server: 真正跑业务的后端节点;
- NAT 模式: 改写目的 IP, 请求与响应都过 director;
- TUN 模式: IP 隧道封装, 响应不经 director;
- DR 模式: 只改目的 MAC, 性能最高但要求同一广播域;
- FULLNAT: 同时改源与目的地址, 解决跨网段部署问题;

## 三种模式的数据路径差在哪？

```text
NAT:   客户端 → director(改目的IP为RS) → RS → 网关指回 director(改源IP为VIP) → 客户端
TUN:   客户端 → director(IPIP 再封一层) → RS → 解封装 → 直接回客户端
DR:    客户端 → director(改目的MAC) → RS(网卡收到但仍判 VIP) → 直接回客户端
```

| 项 | NAT | TUN | DR |
| --- | --- | --- | --- |
| 改什么 | 目的 IP 与端口 | 外层加 IP 隧道 | 目的 MAC |
| 回程过 director | 必须 | 否 | 否 |
| 网络要求 | 可跨网段 | 可跨机房, RS 要支持隧道 | 与 RS 同广播域 |
| director 压力 | 最大, 双向流量都过 | 小 | 最小 |
| RS 配置 | 网关指向 director | lo 上配 VIP | lo 上配 VIP 并抑制 ARP |
| 端口改写 | 支持 | 不支持直接改端口 | 不支持改端口 |

- 选型: 同机房优先 DR, 跨机房用 TUN, 网络改造受限时用 NAT;
- DR 的关键: `arp_ignore=1` 与 `arp_announce=2`, 否则 RS 会抢答 VIP 的 ARP;
- RS 的 VIP: 配在 `lo` 上, 掩码常写成 `/32`, 让 VIP 可被内核本地接收;

## NAT 模式怎么工作？

- 请求: 客户端发往 VIP, director 改目的地址为某台 RS, 源地址保持不变;
- 响应: RS 的网关必须指向 director, 否则回包绕过 directer 导致连接断;
- 回程改写: director 把源地址从 RS 的 IP 改回 VIP 再发回客户端;
- 代价: 双向流量都过 director, 带宽与连接表是瓶颈;
- 优点: 部署简单, 只要能路由到 RS 就能用;

## TUN 模式怎么工作？

- 封装: director 把原始 IP 包整个封进新的 IP 包, 目的地址是 RS 的 IP;
- 解封装: RS 收到后剥掉外层, 内层目的地址仍是 VIP, 由 `tunl0` 接收;
- 回程: RS 直接路由回客户端, 不经 director;
- 代价: 两端要做隧道配置, MTU 变小, 需要处理分片;
- 优点: director 只承担入向流量, 可跨机房部署;

## DR 模式怎么工作？

- 原理: director 只改以太网帧的目的 MAC, IP 报文一律不动;
- 接收: RS 的网卡收到帧, 目的 IP 是自己的 VIP, 内核照常交给上层;
- 回程: RS 用自己的网关直接把响应发给客户端, 源 IP 仍是 VIP;
- 前提: director 与 RS 必须在同一广播域, 通过 ARP 找到 MAC;
- 常见坑: RS 若不抑制 ARP, 会应答 VIP 的 ARP 请求, 流量绕过 director;

## 调度与会话保持怎么办？

| 算法 | 依据 | 适用 |
| --- | --- | --- |
| rr | 轮询 | 后端同质 |
| wrr | 加权轮询 | 机器配置不同 |
| lc | 最少连接 | 请求耗时差异大 |
| wlc | 加权最少连接 | 默认常用 |
| sh | 源地址哈希 | 需要简单会话粘性 |

- 会话保持: 用 `persistent` 超时把同一来源固定到同一台 RS;
- 无状态化优先: 能共享会话就共享, 比粘性更抗故障;
- 健康检查: 用 `keepalived` 的 TCP 或 HTTP 检查摘除坏节点;
