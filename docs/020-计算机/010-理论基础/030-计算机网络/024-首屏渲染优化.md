# 首屏渲染慢，可以怎么优化？

## 常见问题

- 优化首屏渲染的方式有哪几种？
- 如何减少页面渲染的时间？
- 简述图片的懒加载原理

## 概念索引

- 首屏: 用户不滚动就能看到的那部分区域;
- 关键渲染路径: 从 HTML 到首帧的最短链路;
- 关键 CSS: 首屏必需的样式, 内联进 HTML;
- 预加载: 提前以高优先级发起资源请求;
- 懒加载: 资源进入视口才去加载;
- 长任务: 超过 50ms 的主线程任务, 会推迟渲染;
- 虚拟列表: 只渲染视口内的列表项;

## 首屏时间花在哪里？

| 阶段 | 主要成本 | 对应手段 |
| --- | --- | --- |
| 网络 | DNS、TLS、TTFB | CDN、HTTP/2、预连接 |
| HTML 解析 | 文档体积、阻塞脚本 | 服务端渲染、defer |
| 样式 | 阻塞渲染的 CSS | 关键 CSS 内联 |
| JS | 下载、解析、执行 | 代码分割、按需加载 |
| 渲染 | 布局与绘制 | 减少 DOM、避免同步布局 |

- 首屏只关心可见区域: 屏外内容可以延后;
- 优先级: 先让首帧出现, 再让页面可交互;

## 有哪些具体手段？

- 服务端渲染或静态预渲染: 首字节就是完整 HTML;
- 关键 CSS 内联: 首屏样式随文档一次到达;
- 资源提示: preconnect 建连, preload 抢优先级, prefetch 预取下一步;
- 脚本策略: 非关键脚本用 defer, 独立统计脚本用 async;
- 代码分割: 路由级动态 import, 首屏只加载必要包;
- 骨架屏: 先给结构占位, 同时压住 CLS;

```html
<link rel="preconnect" href="https://cdn.example.com" />
<link rel="preload" as="image" href="/hero.webp" />
<script src="/app.js" defer></script>
```

- preconnect: 提前完成 DNS 与 TLS, 适合第三方域;
- preload: 提前下载, 但不保证不被其他资源挤掉;

## 怎么减少页面渲染时间？

- 减少节点: 扁平化 DOM, 合并无意义的包装层;
- 减少重排: 批量读写, 动画用 transform 与 opacity;
- 拆长任务: 分片执行、Web Worker、调度让出主线程;
- 虚拟列表: 长列表只保留视口内节点;
- 内容可见性: content-visibility: auto 跳过屏外渲染;
- 缓存布局查询: 反复读 offsetTop 先取一次存变量;

```css
.offscreen {
  content-visibility: auto;
  contain-intrinsic-size: 500px; /* 给个估算高度, 避免滚动条跳动 */
}
```

## 图片懒加载的原理是什么？

- 核心: 视口外不给真实地址, 只留占位;
- 约定: 真实地址放在 data-src, 触发后再写回 src;
- 方案一: IntersectionObserver 监听元素是否进入视口;
- 方案二: 滚动监听加 getBoundingClientRect 判断, 需要节流;
- 原生: loading="lazy" 交给浏览器, 代码最省;
- 占位: 给宽高或模糊小图, 避免加载后跳动;

```js
const io = new IntersectionObserver((entries, obs) => {
  for (const entry of entries) {
    if (!entry.isIntersecting) continue
    const img = entry.target
    img.src = img.dataset.src
    obs.unobserve(img)
  }
})
document.querySelectorAll('img[data-src]').forEach((img) => io.observe(img))
```

- 提前量: rootMargin 设 200px, 让图片在进入视口前就开始加载;
- 注意: 懒加载会推迟 LCP, 首屏大图不要懒加载;

## 效果怎么量？

- 指标: FCP、LCP、TTI、CLS 一起看;
- 工具: Lighthouse 给建议, Performance 面板看主线程;
- 线上: PerformanceObserver 采集 LCP 与 CLS;
- 目标: LCP 2.5 秒内, CLS 0.1 以下;
