# HTTP 有哪些方法，常见状态码各表示什么？

## 常见问题

- HTTP 的方法有哪些？
- 简述常见的 HTTP 状态码的含义（301，304，401，403）
- HTTP 中 GET 和 POST 区别

## 概念索引

- 方法: 请求起始行里的动作词;
- 安全方法: 不改变服务端资源状态;
- 幂等: 同一请求重复执行, 效果与执行一次相同;
- GET 与 POST: 语义不同, 但都由同一个 HTTP 报文格式承载;
- 状态码: 三位数字, 首位决定类别;
- 301: 永久重定向;
- 304: 协商缓存命中, 资源未变;
- 401: 没有认证或凭证无效;
- 403: 已认证但无权限, 与 401 按「身份」和「权限」区分;

## HTTP 定义了哪些方法？

| 方法 | 语义 | 安全 | 幂等 |
| --- | --- | --- | --- |
| `GET` | 取资源表示 | 是 | 是 |
| `HEAD` | 只取首部 | 是 | 是 |
| `OPTIONS` | 查询支持的方法 | 是 | 是 |
| `POST` | 提交数据, 由服务端决定处理 | 否 | 否 |
| `PUT` | 用完整表示替换资源 | 否 | 是 |
| `PATCH` | 局部修改资源 | 否 | 否 |
| `DELETE` | 删除资源 | 否 | 是 |
| `TRACE` | 回显请求, 诊断链路 | 是 | 是 |
| `CONNECT` | 让代理建立隧道 | 否 | 否 |

- 语义由规范约定, 服务端可以不照做, 但缓存与代理会按约定行事;
- `PUT` 带完整表示, 重复执行结果相同, 所以幂等;
- `PATCH` 常写增量, 重复执行会叠加, 所以非幂等;
- `CONNECT` 用在 HTTPS 代理与隧道场景, 响应后管道里跑的是原始字节;

## 安全和幂等为什么重要？

- 重试: 幂等方法可以被网关或客户端放心重试;
- 缓存: 安全方法可以被缓存、预取与爬虫抓取;
- 预检: 非简单方法会触发跨域预检, 多一次往返;
- 设计: 写接口做成幂等, 才能靠重试兜底超时;

## 状态码怎样分段？

| 首位 | 类别 | 含义 | 例子 |
| --- | --- | --- | --- |
| 1xx | 信息 | 请求已收到, 继续处理 | `100`、`101` |
| 2xx | 成功 | 请求被正常处理 | `200`、`201`、`204`、`206` |
| 3xx | 重定向 | 需要附加操作 | `301`、`302`、`304`、`307` |
| 4xx | 客户端错误 | 请求本身有问题 | `400`、`401`、`403`、`404`、`429` |
| 5xx | 服务端错误 | 服务端处理失败 | `500`、`502`、`503`、`504` |

- 状态码只表达结果类别, 细节看响应体与首部;
- `204` 与 `304` 都不带响应体;
- `206` 配合 `Range` 做分片下载与拖动播放;

## 301、302、304、401、403 分别是什么？

| 状态码 | 语义 | 关键行为 |
| --- | --- | --- |
| `301` | 永久重定向 | 可被缓存, 搜索引擎换索引 |
| `302` | 临时重定向 | 不更新索引, 每次仍走原地址 |
| `304` | 未修改 | 条件请求命中, 不返回主体 |
| `401` | 未认证 | 缺凭证或凭证失效, 带 `WWW-Authenticate` |
| `403` | 禁止访问 | 身份已确认, 但无权访问该资源 |

- 301 与 302 的历史行为: 不少客户端把非 `GET` 请求改成 `GET` 再跳;
- 要保住方法与请求体, 用 `307` 或 `308`;
- 304 必须由条件请求触发, 服务端不能主动返回;
- 401 的出路是「去登录」, 403 的出路是「换权限」;

```http
GET /app.js
If-None-Match: "v7"

HTTP/1.1 304 Not Modified
ETag: "v7"
```

## 常见坑

| 坑 | 后果 | 修正 |
| --- | --- | --- |
| 权限不足返回 401 | 前端误判为登录过期 | 无权限用 403 |
| 304 带响应体 | 客户端解析错乱 | 304 只带首部 |
| 302 跳转丢请求体 | 写接口重试失败 | 用 307 或前端自己跳 |
| 把 502 当业务错误 | 排查方向跑偏 | 502/504 先查网关与上游 |
| 用 200 包业务错误码 | 缓存与监控失真 | 状态码表达结果, 业务码放响应体 |

## GET 与 POST 有什么区别？

| 维度 | GET | POST |
| --- | --- | --- |
| 语义 | 取资源表示 | 提交数据, 由服务器定义副作用 |
| 幂等 | 是, 协议要求 | 否, 重复提交会重复执行 |
| 缓存 | 可被缓存与预取 | 默认不缓存 |
| 参数位置 | URL 查询字符串 | 请求体 |
| 长度 | 受 URL 长度限制 | 只受服务器与内存限制 |
| 可见性 | 出现在历史、日志、Referer | 不进 URL, 但仍需加密保护 |

- 上限来自实现: Chrome URL 约 8182 字节, 并非协议规定;
- 安全误区: POST 只是不放进 URL, 明文 HTTP 下一样能被读取;
- 幂等价值: GET 可安全重试与预取, POST 重试要带幂等键;
- 编码: POST 表单用 `application/x-www-form-urlencoded`, JSON 用 `application/json`;
- 取舍: 查询用 GET, 有副作用用 POST, 部分更新可用 `PATCH`, 整替换用 `PUT`;
