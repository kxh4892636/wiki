# localStorage、sessionStorage 和 cookie 有什么区别？

## 常见问题

- localstorage 与 cookie 的区别是什么？
- sessionStorage 和 localStorage 有什么区别？

## 概念索引

- cookie: 会随每个同源请求自动发出去的小段文本;
- localStorage: 同源共享、长期保存的键值存储;
- sessionStorage: 只在当前标签页生命周期内有效;
- 同源: 协议、域名、端口三者都相同;
- 容量: cookie 约 4KB, Web Storage 约 5MB;
- 同步 API: Web Storage 读写都在主线程执行;
- IndexedDB: 容量大、异步、可建索引的浏览器数据库;

## 三者有哪些硬差别？

| 项 | cookie | localStorage | sessionStorage |
| --- | --- | --- | --- |
| 容量 | 约 4KB | 约 5MB | 约 5MB |
| 生命周期 | 可设过期时间 | 手动删除前一直存在 | 标签页关闭即清 |
| 随请求发送 | 是 | 否 | 否 |
| 作用域 | 可按 Domain、Path 收窄 | 同源全部页面 | 同源且同标签页 |
| 读写方式 | document.cookie 字符串 | getItem 与 setItem | getItem 与 setItem |
| 服务端可见 | 是, 除非 HttpOnly | 否 | 否 |

- cookie: 为无状态的 HTTP 补一份会话标识, 天生贴近网络层;
- Web Storage: 纯客户端容器, 不参与请求, 不会额外增加流量;
- 性能: cookie 每次请求都带, 体积大时明显拖慢首字节;

## cookie 有哪些属性？

| 属性 | 作用 |
| --- | --- |
| Expires 与 Max-Age | 过期时间, 都不设则为会话 cookie |
| Domain 与 Path | 决定发送范围 |
| Secure | 只在 HTTPS 下发送 |
| HttpOnly | JS 读不到, 挡 XSS 窃取 |
| SameSite | Lax、Strict、None, 缓解 CSRF |

- Max-Age 优先于 Expires, 单位是秒;
- SameSite=Lax 是多数浏览器的默认值;
- 数量限制: 单域名约 50 个, 每个约 4KB;

## localStorage 有哪些坑？

- 同步阻塞: 大对象序列化会卡住主线程;
- 只能存字符串: 对象要先 JSON.stringify;
- 没有过期: 需要自己塞时间戳字段判断;
- 跨标签页: 用 storage 事件同步状态;
- 不安全: 任何脚本都能读, 不要存 token;

```js
localStorage.setItem('theme', 'dark')
window.addEventListener('storage', (e) => {
  if (e.key === 'theme') console.log('其他标签页改成了', e.newValue)
})
```

- storage 事件: 只在其他标签页变更时触发, 当前页不触发;

## sessionStorage 的边界在哪？

- 生命周期: 刷新保留, 关闭标签页即清;
- 复制标签页: 新标签页拿到一份副本, 之后互不影响;
- 作用域: 同源同标签页, 同源 iframe 可共享;
- 适用: 表单草稿、单次流程的中间状态;
- 不适用: 需要跨标签页共享的登录态;

## 什么时候该用 IndexedDB？

- 容量: 按配额分配, 可达数百 MB;
- 异步: 不阻塞主线程, 适合大批量数据;
- 能力: 事务、索引、二进制, 可存文件;
- 适用: 离线应用、大缓存、日志队列;
- 封装: 原生 API 冗长, 常用 idb 或 Dexie;
- 选型: 少量配置用 localStorage, 数据活用 IndexedDB;
